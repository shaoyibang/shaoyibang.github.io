先让它不用 JS 也能用

不是复古情怀，而是最便宜的性能预算和最强的健壮性测试。三条约束，能救掉一大半的返工。

我做这个站点的第一件事，是把所有内容写成静态 HTML，然后再往上加 JavaScript。听起来很朴素，但顺序反过来——先想好交互再补内容——你几乎一定会写出一个"JS 一挂就全白"的页面。

这不是关于禁用 JS 的极客洁癖。真实世界里的网络会抖、CDN 会挂、公司代理会拦脚本。你的页面在这些时候是显示内容，还是显示一片空白，取决于你写第一行代码时的顺序。

约束一：内容必须在 HTML 里，不能在 JS 里

反例很常见：一个空 <div id="app"></div>，所有文字靠接口返回后渲染。它的代价是用户要等"HTML → JS 下载 → 解析 → 请求 → 渲染"四跳才能看见第一个字。

我的规则是：首屏的每一个字都必须存在于初始 HTML 中。这个站的首页有十张卡片、几十个标签，全部是静态标签，JS 只负责交互：命令面板、主题切换、随机语录。所以就算 JS 完全加载失败，你依然能读完首页、点进任何一篇文章。

一个自检方法：把浏览器的 JS 关掉，刷新页面。如果还能读完主要内容并完成导航，这个页面的骨架就是对的。

约束二：渐进增强，而不是优雅降级

两者的区别在于默认状态是什么。优雅降级是"我先做炫的，再想办法兜底"，于是兜底永远排在最后，永远没时间做。渐进增强是"我先做能用的，再往上加体验"。

具体到代码里，我尽量让"没有 JS"这一态不需要额外写代码，只要别把功能焊死在 JS 上。比如导航就是普通的 <a>，主题切换才需要脚本；文章列表是普通链接，命令面板只是加速器——没有它，站点依然完整。

<!-- 好：没有 JS 也是完整可用的链接 -->
<a class="post-row" href="blog/bento-layout.html">
  <strong>Bento 网格为什么这么耐看</strong>
</a>

<!-- 差：href="#" + 点击事件，JS 一挂就死 -->
<a class="post-row" href="#" onclick="openPost(3)">…</a>

约束三：性能预算先定，再动手

我给这个站点定的预算是：首屏 HTML + CSS 小于 60KB，阻塞渲染的请求只有两个（样式表和字体）。为了守住它，我做了三个取舍：

  • 不用 UI 框架。一个个人站点不需要虚拟 DOM，手写 CSS 反而更快也更小。
  • 图标全部内联 SVG。省掉一整套图标字体的下载，还能直接用 currentColor 跟随主题变色。
  • 字体只加载需要的字重。标题 500/600/700，正文 400/500/600，其余不加载，并配好系统字体兜底栈。

字体这里有个细节值得单独说：font-display: swap 是必须的，但更重要的是兜底字体要选对。我把 system-ui 和中文系统字体放在链尾，所以即使 Google Fonts 被墙，页面也不会出现文字闪烁或布局跳动得离谱。

这三条约束换来了什么

最直接的收益是稳健：断网、代理拦截、脚本出错，站点都还能读。其次是速度——没有水合、没有运行时，首屏几乎是"下图即见"。

但我觉得最大的收益是设计上的。当你不能靠 JS 补救布局时，你会被迫把结构想清楚：什么是一级信息、什么是可选的增强、状态该用什么原生元素表达。这三条约束像一把尺子，把"以后再说"的模糊决策提前逼了出来。

顺带说一句，键盘用户会感谢你：原生 <a>、<button> 自带焦点、回车和读屏支持。你少写的那几百行 JS，很多本来就是在手搓这些。
